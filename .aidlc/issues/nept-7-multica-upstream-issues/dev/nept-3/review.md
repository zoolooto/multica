# NEPT-3 评审记录

评审对象：`feature/nept-3`，固定点 `origin/feature/nept-7-multica-upstream-issues`。
评审方式：规范轴、需求轴各一个只读 subagent 并行评审，报告由队长判定后落盘。

## 第 1 轮（HEAD `ed56af9fe`）

### 规范轴

结论：需改。

硬违规：

1. 看门狗没有任何可见性门控。`ChatWindow` 关闭时仍挂载并保留 `activeSessionId`，断线期间仍会每 10s 对一个用户看不见的会话失效并重取。
2. 注释断言「只有曾经连上又断开的客户端才会进入 `reconnecting`」不成立：首次握手失败后的第一次重试同样是 `reconnecting`，因此「从未连上」的客户端也会被判为降级；对应测试用例名同样基于错误前提。
3. 纯逻辑测试（状态矩阵、轮询常量区间）被放进 banner 组件测试文件，未与实现同目录。
4. `chat-page` 用平台镜像 `getCurrentWsId()` 取 wsId，而 `useChatController` 已返回 `wsId`；同仓库另一处调用点用的正是 controller 值。
5. banner 接线没有页级/窗口级覆盖：既有两个测试文件都把 socket 钉成 `connected`，`chat-window` 还把 banner 整个 mock 掉。

异味（不挡）：重复的事故叙述、import 分组被破坏、整模块 mock 未展开原始导出、常量区间断言无行为含义。

### 需求轴

结论：需人（经判定后由实现方在票内处理，见下）。

1. 触发条件只覆盖「客户端已经检测到自己断线」，而 brief 自己把报告主症状归因为「客户端不认为自己断线」（socket 半开、状态停在 `connected`）。按此交付，报告里的卡死场景仍无兜底，brief 前后自相矛盾。
2. `messagesPage` 是无限查询，每个 tick 失效会按已加载页数放大请求，与「长断线不变成请求风暴」的自述冲突。
3. `chatKeys.messages(sessionId)` 在聊天面没有活跃查询，属于空转失效。
4. 关闭的浮动窗仍在后台对账（与规范轴第 1 条同一处）。
5. 表面接线没有回归保护。

### 判定

需改（两轴合并处理）。

需求轴提出的是范围问题：要么承认只覆盖「已检测到的断线」，要么补一条症状级兜底。分诊结论第 1 条已经把缺口写成「进行中的会话没有任何兜底对账」，因此把触发条件扩宽到「有回合正在进行」仍在票内，未改变已定方案，不上升人闸。

返工内容（第 2 轮评审对象，HEAD `e11d13b0c`）：

- 新增健康态兜底：有进行中的回合时，即使 socket 自报 `connected`，也按较慢间隔只轮询 `pendingTasks(wsId)` 与 `pendingTask(sessionId)`，让丢帧的回合能收敛。
- 转录只在「确认断线瞬间」与「回合结束（或换成下一个 task）」时重取，不再每 tick 全量失效。
- 去掉空转的 `chatKeys.messages`。
- 看门狗加 `enabled` 门控：关闭的浮动窗、非聊天路由不再对账。
- 修正 `reconnecting` 语义注释与用例名。
- wsId 统一取 controller 值；纯逻辑测试移到 `chat/lib/realtime-watchdog.test.ts`；删除常量区间断言。
- 两个页级/窗口级测试改为可变 socket 状态，断言降级时 banner 出现、健康时不出现。
- 文案从「连接已断开」改为「连接不可用」，覆盖首次握手失败也会进入重连的情况（8 个语言包同步）。

## 第 2 轮（HEAD `e11d13b0c`）

### 规范轴

结论：通过。上一轮 5 条硬违规全部解决，新增两条路径（降级节奏、健康态 pending 轮询）实现与 brief 一致，单定时器、清理、`enabled` 门控、`/chat` 路由与浮动窗不重复计时均成立。

遗留异味（不挡）：回合结束判定只存 task id、不区分会话；健康态 20s 节奏与「关闭窗口 + 有回合」两条路径没有断言钉住；手写 `setInterval` 与仓库惯用的 `refetchInterval` 不同；事故叙述仍散在多个文件；banner 壳第三次复制；`role=status` 上多余的 `aria-live`。

### 需求轴

结论：通过。上一轮 5 条全部落地，核心时序成立：终态帧丢失时「慢轮询 pending → pending 变空 → task id 变化 → 转录重取」能在 20s 内收敛，断线期间回合结束与连续多回合都覆盖。

记录在案的取舍与盲区：

- 半开连接没有可见提示（banner 只在 `reconnecting` 出现）。brief 已声明不引入心跳判死，交付应表述为「最终收敛 + 已检测断线可见」，不能说成「半开连接也能看见」。
- 丢失终态帧的任务若不属于当前打开的会话，其列表徽标要等用户打开该会话才自愈。
- 会话切换被误判为「回合结束」会多取一次转录（低危）。

### 判定

通过（第 2 轮，两轴均通过）。

通过后顺手修掉两条遗留，与测试一起补回：

- 回合结束的回落改为按「会话 + task id」记录：切换会话不再误触发转录重取；回合在窗口关闭期间结束会记下待回落，重新打开时补一次转录重取。
- 补充断言：健康态节奏确实慢于降级节奏；关闭状态（`connected` 与 `reconnecting` 两种）都不轮询；切换会话不重取目标会话转录；隐藏期间结束的回合在重新打开时补取。
- 常量归位到 `lib/realtime-watchdog.ts`（两条节奏并列），去掉冗余 `aria-live`，注释措辞与实现对齐，`setInterval` 的选型补一行理由。

改动后复跑：`vitest run chat/ locales/` 861 通过；`tsc --noEmit`、`eslint chat/` 无报错。全量 `vitest run` 中 4 个无关用例在全量并发下超时，单文件重跑全部通过（既有 flaky）。
